# QMT 接入规划

## 定位

当前项目首先服务于行情研究、策略开发和历史回测。QMT / MiniQMT 不参与现阶段的数据分析与回测流程，后期仅作为交易执行接口接入。

项目已经通过 `BaseBroker` 预留统一交易接口，并提供不会真实下单的 `QMTBrokerStub`。未来在具备 QMT 环境、账户授权和完整风控后，再新增 `brokers/qmt_broker.py`，避免研究代码直接依赖特定券商运行环境。

## QMT Broker 接口

未来的 QMT Broker 需要实现：

- `connect`
- `get_account`
- `get_positions`
- `get_orders`
- `get_trades`
- `buy`
- `sell`
- `cancel_order`

接口实现需要将 QMT 原始对象转换为项目内部统一的数据结构，并明确处理连接断开、委托失败、部分成交、撤单失败和回报重复等情况。

## 实盘前风控要求

任何真实下单能力启用前，必须至少加入：

- 最大单笔买入金额
- 最大单只股票仓位
- 最大总仓位
- 股票黑名单
- 交易时间检查
- 涨跌停检查
- 一键停止交易
- 人工确认模式

此外应当建立独立的模拟环境、日志与审计记录，并完成小资金、低频率、人工监控下的逐步验证。当前 `QMTBrokerStub` 不导入真实 QMT 库，也不会发送任何委托。
